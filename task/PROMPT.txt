实现本地安全证据包存储，允许使用cryptography库的AES-GCM；所有测试密钥临时生成，不接真实KMS。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 每个对象用独立随机数据密钥，分块AEAD的关联数据绑定包ID、对象ID、版本、块序号、总块数与明文长度；同密钥nonce不可复用。清单认证文件顺序、对象摘要与密钥版本，任意换块、截尾、跨包拼接必须拒绝。
2. 主密钥只包装数据密钥，轮换应重包密钥而不重写数据块；整个包通过新清单原子切换，读取者只能见完整旧版或新版。旧主密钥仅在所有引用清除并完成恢复检查后才能退役，失败不得丢掉最后可解密路径。
3. 实现迁移日志、幂等重试与故障注入，覆盖新密钥包装、清单写入、切换及旧引用清理四阶段；解密先写隔离临时文件，完成清单和全部标签验证后才发布，认证失败不暴露部分明文。

必须覆盖的验收场景：重复nonce拦截、跨对象换块、最后块删除、轮换各阶段进程退出、并发读取及退役过早；恢复后包内容逐字节一致，并证明数据块文件在纯轮换中哈希不变。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
